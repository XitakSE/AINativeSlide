# データ表からの直接ビジュアル化プロトコル (Data-to-Visual Binding)

ユーザーがプロンプトで数値データ（CSV、TSV、Markdown表、Excelペースト等）を提示した場合、エージェントは単なる凡庸なHTMLテーブル出力で終わらせず、データの性質・次元を判定して以下の決定論的ルールで「経営・示唆レベルのビジュアルパターン」へ自動変換してください。

---

## 1. 決定論的パターン判定マトリクス

| 入力データの性質 | 推奨構造パターン | 適用コンポーネント | 変換時の自動計算・装飾 |
| :--- | :--- | :--- | :--- |
| **開始値 ＋ 要因別の増減 ＋ 着地値**<br>（例: 利益ブリッジ、工数・時間削減、人員数変動、解約/顧客数推移、粗利率%・pt、システムレイテンシms） | `waterfall_breakdown`<br>（要因分解・ウォーターフォール） | 戦略コンサル型増減バー<br>実績 vs 予測境界線 | ・各期・各要因の増減額（+ / -）<br>・増減率（%）と差分矢印<br>・スケール自動正規化（単位不問） |
| **2軸のセグメント構成比**<br>（例: 地域別×プロダクト別、市場規模×各社シェア） | `mekko_chart`<br>（2次元マリメッコ） | 2次元Mekkoレイアウト<br>（CSS Flex / Stack） | ・横幅 = TAM/セグメント総量（%）<br>・縦高さ = 内訳シェア（%）<br>・最大シェア要素にハイライト色 |
| **複数候補 × 複数評価軸の採点**<br>（例: ベンダー比較、ツール選定、戦略オプション比較） | `tradeoff_matrix`<br>（トレードオフ比較表） | ハーベイボール<br>推奨列ハイライト枠 | ・定性・定量評価を5段階（●◕◐◔○）へ正規化<br>・推奨案の列に `border-2 border-brand-500` |
| **時系列タスク・工程・マイルストーン**<br>（例: 導入ロードマップ、開発フェーズ、リリース計画） | `step_process` または `timeline_gantt` | ガント・タイムライン<br>マイルストーンダイヤ（◆） | ・期間からCSS Grid幅（`col-span-X`）を算出<br>・重要判定ポイント（Gate）に「◆」を付与 |

## 2. パターン別 具体的変換レシピ

### レシピ1：増減・要因データ ➔ ウォーターフォール変換

#### 入力例（CSV / Markdown）:
```markdown
項目, 数値(単位問わず), 属性
2024実績, 120, baseline
新規顧客開拓, +45, positive
既存解約, -15, negative
単価改善, +20, positive
システム投資, -10, negative
2025見通し, 160, final
```

#### 金額スケール変更 ＆ 非金銭指標（工数・人員・率・ms等）への適用:
ウォーターフォールは金額（円・$・億円）だけでなく、**「開始値 ＋ 増減要因 ＋ 着地値」を持つあらゆる定量的指標**に完全対応します：
* **工数・業務時間**: `120人月 ➔ 仕様標準化 -30 ➔ 自動化 -25 ➔ 監査追加 +5 ➔ 70人月 (42%削減)`
* **人員・組織**: `150名 ➔ 中途採用 +35 ➔ 離職 -10 ➔ 組織再編 -5 ➔ 170名`
* **顧客・契約数**: `2,500社 ➔ 新規獲得 +800 ➔ 解約 -150 ➔ アップセル +120 ➔ 3,270社`
* **比率・マージン**: `65.0% ➔ 原価高騰 -3.5pt ➔ 価格改定 +2.8pt ➔ 64.3%`
* **性能・レイテンシ**: `1,200ms ➔ キャッシュ化 -400ms ➔ クエリ改善 -350ms ➔ 450ms (62%短縮)`

#### ビジュアル化・スケール正規化ルール:
1. **正規化スケール計算**: 描画枠の最大高さ（例: `120px`）に対し、入力の最大累積値 $V_{max}$ から `scale = 120 / V_max` を算出。各バーの高さは `abs(数値) * scale` で厳密比例描画。
2. `baseline` と `final` はベースから立ち上がる全高バー（グレー / ブランド色）として描画。
3. `positive` は緑（`emerald-500`）またはブランド色、`negative` は赤/橙（`rose-500`）の浮動ブロックとして描画。
4. 開始から着地への「差分（例: +40 / +33.3%）」を右肩または上部の **差分矢印（Difference Arrow）** で明示。
5. 実績と予測・To-Beの間に **境界線**（破線＋バッジ）を挿入。
6. コネクタ破線は前ステップのバー端点と同一 $y$ 座標に幾何学的一致させる。

### レシピ2：市場規模 × シェアデータ ➔ マリメッコ変換

#### 入力例:
```markdown
市場セグメント, 市場規模(億円), 自社シェア, 競合A, 競合B
エンタープライズ, 500, 50%, 30%, 20%
ミッドマーケット, 300, 30%, 40%, 30%
SMB, 200, 10%, 20%, 70%
```

#### ビジュアル化ルール:
1. 合計規模 1,000億円 に対し、各列の幅を計算：
   - エンタープライズ: `w-[50%]`
   - ミッドマーケット: `w-[30%]`
   - SMB: `w-[20%]`
2. 各カラム内の高さを自社・競合のシェア%に応じてスタック配置（自社は `bg-brand-600`、競合は `bg-slate-300` / `bg-slate-200`）。
3. 「最もTAMが大きく自社優位な領域（エンタープライズ）」にフォーカス枠またはアノテーションを付加。

---

### レシピ3：採点・選定表 ➔ トレードオフ比較表（ハーベイボール）

#### 入力例:
```markdown
評価項目, 自社推奨案, 従来パッケージA, SaaSサービスB
初期コスト, 安い (5/5), 高い (1/5), 中程度 (3/5)
拡張性, 非常に高い (5/5), 低い (2/5), 高い (4/5)
納期, 2ヶ月 (4/5), 6ヶ月 (1/5), 即時 (5/5)
セキュリティ, 完全準拠 (5/5), 準拠 (4/5), 一部制約 (3/5)
総合判定, ◎ 採用, ✕ 不可, △ 保留
```

#### ビジュアル化ルール:
1. `(5/5)` ➔ `●`（満点 / 100%）、`(4/5)` ➔ `◕`（75%）、`(3/5)` ➔ `◐`（50%）、`(2/5)` ➔ `◔`（25%）、`(1/5)` ➔ `○`（0%）に自動置換。
2. 「自社推奨案」の列ヘッダーに `★ 推奨 (Selected)` バッジを付け、列全体を `bg-brand-50/60 border-2 border-brand-500` で包む。
3. スライド上部のリード文で「総合スコープとセキュリティの観点から自社推奨案を採用すべきである」と動詞で結論付ける。

## 3. 単一ファイルHTMLにおける制約の遵守

- **外部ライブラリ（Chart.js等）は一切使用しない**: すべて Tailwind CSS の幅・高さパーセンテージ（`w-[..%]`, `h-[..%]`）および Flex/Grid レイアウトで描画すること。
- **データ数値の直書き**: グラフ内のバーやスタックには、必ず具体的な数値（`120億`, `50%`）を `<span class="text-xs font-mono font-bold">` で明記すること。
